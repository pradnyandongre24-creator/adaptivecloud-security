AdaptiveCloud: Complete Architectural & Technical Reference Guide

An enterprise-grade, full-stack autonomous cloud resilience, root cause analysis (RCA), and predictive hardware failure platform. Aligned with MITRE ATT&CK, the UNSW-NB15 intrusion dataset, and Amazon Web Services (AWS) infrastructure.

1. Executive Summary & Problem Statement

The Problem in Modern Cloud Computing

In distributed cloud environments and hybrid data centers, two major operational silos create catastrophic downtime:

  • The Cyber Defense Silo (SIEM / SOC): Volumetric cyberattacks (DDoS floods, credential stuffing, cryptominers) propagate in milliseconds (<500ms). Traditional SOC teams manually correlate alerts, causing the average Mean Time to Detect (MTTD) to exceed 16 days.
  • The Hardware Health Silo (DevOps / SRE): Cyberattacks inflict severe physical hardware wear:
    • Volumetric packet floods cause Linux kernel SoftIRQ starvation and NIC socket exhaustion.
    • Cryptomining daemons peg CPU cores at 100%, causing thermal throttling and silicon electromigration.
    • Rapid brute-force logging causes disk I/O thrashing and rapid EBS storage saturation.

The Solution: AdaptiveCloud

AdaptiveCloud bridges these two silos into a single closed-loop control plane:

  • Two-Tier ML Threat Classification: Evaluates telemetry in <5ms to detect canonical attack families and specific MITRE ATT&CK techniques.
  • Forensic Root Cause Analysis (RCA):** Reconstructs millisecond propagation timelines ($T+00.0\text{s} \rightarrow T+03.9\text{s}$) and calculates multi-deviation baseline shifts.
  • Autonomous Self-Healing: Neutralizes threats in <400ms with zero-human latency while maintaining safety guardrail vetoes.
  • Predictive Maintenance: Uses Theil-Sen robust regression to calculate Time-to-Failure (TTF) and correlates cyber strain with physical degradation.

2. The 4 Core Platform Pillars

Pillar 1: Two-Tier Threat Detection & Classification (/)

Evaluates a 5-dimensional behavioral telemetry vector:

  1. cpu: CPU Core Utilization Percentage (0–100%).
  2. ram: Resident Memory Allocation Percentage (0–100%).
  3. failed_logins: Authentication failure rate.
  4. inbound_traffic: Incoming packet/bandwidth velocity (packets/second).
  5. active_connections: Sockets in ESTABLISHED or SYN_RECV states.

Pillar 2: Root Cause Analysis (RCA) Engine (/rca)

Synthesizes four diagnostic elements:

  • Evidence-Grounded Hypotheses: Generates probabilistic hypotheses linked directly to quantified telemetry shifts.
  • Multi-Factor Deviations: Calculates deviation ratios against baseline normal operations (e.g. Inbound traffic 783.3x deviation).
  • Millisecond Causal Timeline: Reconstructs propagation from T+00.0s (network ingress) to T+01.5s (socket exhaustion) and T+03.9s (service disruption).
  • Differential Diagnosis: Rules out routine tasks like scheduled cron backup jobs.

Pillar 3: Autonomous Self-Healing & Governance (/healing)

Executes a 5-stage automated remediation runbook:

  1. Telemetry Threshold Triggered
  2. Two-Tier ML Inference (<5ms)
  3. Edge Rate-Limit Rule Applied (AWS WAFv2 / Perimeter Firewall)
  4. Host Socket Backlog Throttling & TCP SYN Cookie Tuning
  5. Post-Healing Verification Normalization Probe
Safety Guardrail Veto Authority: Critical system processes (systemd, sshd, lsass.exe) and gateway IP addresses can NEVER be terminated or blocked by automated playbooks.

Pillar 4: Predictive Maintenance & Hardware Degradation (/maintenance)

Uses the Theil-Sen Robust Regression Estimator to eliminate false alarms from transient network spikes:

Slope = Median( (y_j - y_i) / (t_j - t_i) ) for all i < j
  • Calculates pairwise slopes across all timestamps.
  • Takes the median slope, giving a breakdown point of 29.3% against outliers.
  • Forecasts exact Time-to-Failure (TTF) for EBS Volume Storage Depletion and Out-Of-Memory (OOM) crashes.
